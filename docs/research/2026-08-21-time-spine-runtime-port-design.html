Python oracle parity · no product shortcuts

Time-spine runtime —
축약 경로를 정본 흐름으로 되돌린다

이 작업은 table model 하나를 더하는 수준이 아니다. 이미 포팅된 manifest·node·renderer 위에 source 선택, metric-evaluation recipe, dataflow planning, 여섯 SQL 변환 경로를 순서대로 연결해야 한다.

Implementation result

Option A의 TS0–TS5를 완료했다. 새 제품 개념 없이 upstream 0.210.0의 source 선택, cumulative·conversion·offset planner, 여섯 SQL 변환과 shared CTE 경계를 포팅했다. 24개 targeted case를 더한 136-case corpus가 모든 지원 dialect에서 일치하며 전체 test와 공개 artifact gate가 통과한다.

01 · DECISION

부분 patch가 아니라 upstream 실행 파이프라인을 포팅한다

현재 축약된 buildSingleMetricBranch에 type별 분기를 계속 붙이면 Python의 metric-evaluation plan과 다시 갈라진다.

first

표준 경로

DAY spine, explicit join-to-spine, cumulative, conversion, standard offset를 먼저 닫아 Monomer query를 unblock한다.

then

전체 parity

custom grain, multiple spine, sub-day, nested offset와 filter 조합까지 upstream 0.210.0 의미를 보존한다.

never

제품 shortcut 없음

Monomer 전용 DAY 가정, Control SQL patch, 숨은 fallback, capability flag를 public engine에 넣지 않는다.

02 · CURRENT GAP

Type은 있지만 runtime wiring이 비어 있다

Source selectionKotlin TimeSpineSource에는 upstream choose_time_spine_sources가 없다. compatible standard/custom source를 고르는 정본 규칙이 아직 실행되지 않는다.
Engine compositionExplainPipeline.timeSpineReadNodes와 timeSpineMetricTimeNodes가 명시적으로 emptyMap()이다.
PlannerDataflowPlanBuilder는 cumulative·conversion·metric offset을 NotImplementedError로 종료한다. Python 2,489줄에 대응하는 Kotlin builder는 849줄의 축약 경로다.
SQL conversionJoinOverTimeRange, JoinToTimeSpine, JoinToCustomGranularity, JoinConversionEvents, 두 custom-offset visitor가 deferred다.
Already presentManifest model, TimeSpineSource 기본 map, time-spine dataset converter, dataflow node family, join-expression helpers, cumulative/conversion metric-evaluation node는 이미 있다.

PROGRESS의 “W15 time spine wiring done”은 corpus 상태를 과대해석한 기록이다. 기준선은 실제로 112 PASS / 0 FAIL이지만 선택된 29 explain case는 simple·derived·ratio 중심이며, 위 deferred runtime을 통과하지 않는다.

03 · UPSTREAM MAP

Python에서는 세 계층이 하나의 계약을 이룬다

TimeSpineSource요청 time spec에 compatible한 standard source를 고르고 custom grain은 그 column을 선언한 source에 고정한다.
DataflowPlanBuildermetric-evaluation plan을 방문해 cumulative·conversion·derived input recipe를 만들고, before/nested/after aggregation 위치에 적절한 spine join node를 삽입한다.
SQL visitor선택된 spine dataset을 SQL source로 바꾸고 time-range, equality, conversion-event, custom-offset join expression을 렌더 가능한 SQL plan으로 낮춘다.

04 · TARGET STRUCTURE

기존 upstream vocabulary로 수렴한다

  1. ExplainPipeline이 manifest에서 standard spine source를 만들고 raw read node와 metric-time transform node를 구성한다.
  2. SourceNodeSet이 semantic-model source와 spine source를 같은 planning input으로 제공한다.
  3. DataflowPlanBuilder가 이미 포팅된 MetricEvaluationPlan visitor와 upstream recipe 흐름을 사용한다.
  4. cumulative·conversion·offset·join-to-spine은 기존 dataflow node로 표현한다. 새 node나 별도 planner hierarchy를 만들지 않는다.
  5. DataflowNodeToSqlSubqueryVisitor가 upstream 메서드를 idiomatic Kotlin으로 포팅하고 기존 SqlJoinBuilder helper를 재사용한다.

현재 simple/derived/ratio 축약 구현은 바로 삭제하지 않는다. upstream visitor 흐름이 동일 corpus를 통과한 wave에서 교체하고, dual path나 feature flag 없이 하나의 canonical builder만 남긴다.

05 · PORT WAVES

의존 순서대로 여섯 wave로 나눈다

TS0 · Oracle gate현재 corpus에 targeted explain case를 추가한다. standard join, cumulative, conversion, offset, custom grain, multiple spine의 Python SQL을 먼저 고정한다.
TS1 · SourceschooseTimeSpineSources, engine composition의 read/metric-time node map, source selection unit test를 포팅한다. 기존 atemporal empty-spine 계약을 유지한다.
TS2 · Plannermetric-evaluation plan visitor, cumulative/conversion output builder, simple/derived input recipe, before/nested/after aggregation spine join을 upstream 구조로 수렴시킨다.
TS3 · Standard SQLtime-range join, explicit time-spine join, conversion event join과 standard offsetWindow/offsetToGrain SQL 변환을 포팅한다. 여기서 Monomer의 daily path가 열린다.
TS4 · Custom/fullcustom granularity join, 두 custom-offset visitor, multiple/sub-day spine 선택, filter·multi-metric 조합을 닫는다.
TS5 · Release gatetargeted corpus 전 dialect parity, 기존 112-case regression, 전체 test, verifyPublicArtifact, 남은 time-spine NotImplementedError 0건을 확인한다.

각 wave는 test-green commit 단위다. 하지만 public artifact를 “time-spine complete”로 선언하는 기준은 TS5다. 중간 wave를 완료 상태로 포장하지 않는다.

06 · CONFORMANCE

112 PASS를 유지하면서 빠진 축을 추가한다

Standardsimple join_to_timespine, MetricTime + bound, cumulative all-time/window/grain-to-date, conversion with/without window, standard offset window/to-grain.
Compositionnested cumulative input, derived/ratio offset, multiple metrics, query/metric filter, selected·unselected time filter, non-additive input.
GrainDAY source → coarser query, multiple standard sources, sub-day source, custom grain, date part와 custom offset.
DialectDefault, Trino, BigQuery, Snowflake, Databricks, Redshift, DuckDB, Postgres. SQL normalizer는 기존 의미 보존 규칙만 사용한다.
Negativeatemporal query + empty spine은 성공, time-dependent query + empty/incompatible spine은 명시적 configuration error.

Upstream snapshot 경로에는 이름 기준으로 cumulative 438, conversion 336, offset 549, time_spine 317, custom_granularity 400개 파일이 있다. 서로 겹치므로 합산하지 않으며, TS0에서 의미 조합을 대표하는 최소 matrix를 추출한 뒤 full snapshot family로 확대한다.

07 · BOUNDARIES

새 제품 개념과 실행 책임은 만들지 않는다

  • python_oracle/upstream은 읽기 전용이며 기준 version은 0.210.0으로 고정한다.
  • 엔진은 manifest → SQL까지만 소유한다. warehouse 연결·table 생성·data-quality 검사는 넣지 않는다.
  • Monomer의 connector, Catalog, TimeSpine 저장 모델을 public library에 역으로 노출하지 않는다.
  • 새 lifecycle, capability registry, fallback SQL, version identity를 만들지 않는다.
  • upstream domain 이름과 기존 dataflow node를 유지하고, Kotlin에서 필요한 immutable collection·sealed type 표현만 사용한다.
  • 현재 atemporal behavior와 모든 기존 public artifact test는 회귀 불가 gate다.

08 · FROZEN SCOPE

표준 경로부터 full parity까지 같은 task에서 완료한다

2026-08-21 사용자 결정으로 Option A를 확정했다.

확정 · Option ATS0→TS5 전체를 진행한다. TS3에서 Monomer를 unblock하지만 task 완료와 새 public release 후보는 custom/multiple-spine까지 닫힌 TS5로 본다.
기각 · Option BTS3까지만 먼저 release하고 TS4를 후속 task로 두지 않는다. Public library의 부분 포팅 상태와 이중 완료 기준을 만들지 않는다.

현재 기술 blocker는 없다. 필요한 upstream source, node model, renderer helper, Python snapshots가 모두 로컬에 있다. 새 blocker가 확인되면 우회하지 않고 구현을 멈춰 보고한다.

완료 증거

기존 112 corpus를 수정하지 않고 upstream fixture/snapshot에서 24개 time-spine query를 추가했다. 최종 결과는 136 PASS / 0 FAIL / 0 UNIMPLEMENTED / 0 ERROR이며, ./gradlew test와 ./gradlew verifyPublicArtifact도 통과했다.
